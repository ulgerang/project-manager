# 제품 기획

## 목적

Codex와 Claude Code로 여러 프로젝트를 진행하는 사용자가 현재 상황, 확인할 사항, 다음 할 일을 한눈에 파악한다. 웹 관리 화면과 바탕화면 위젯은 동일한 서버 데이터를 사용한다.

## 확정된 범위

- 약 7개 프로젝트를 탭 전환 없이 전체 목록에서 훑어볼 수 있다.
- 위젯의 접힌 항목은 프로젝트 이름 1줄, 내 상태 최대 2줄, AI 상태 1줄 순으로 표시한다.
- 사용자는 상세 화면에서 자신의 상태를 직접 작성·수정한다. 펼친 화면에도 내 상태 전체가 먼저, AI 상태 전체가 그다음에 표시된다.
- 드래그 손잡이로 순서를 조정하고, 키보드로도 위/아래 이동 버튼을 사용할 수 있다. 순서는 서버에 일괄 저장한다.
- 삭제 버튼은 확인 후 프로젝트를 목록에서 제외한다. 할 일·메모·활동 기록은 보존하며 실제 프로젝트 폴더나 소스는 삭제하지 않는다.
- 클릭하면 현재 작업, 다음 할 일, 메모, 최근 기록을 펼친다.
- 웹 화면에서 전체 편집과 날짜별 기록 조회를 제공한다.
- 바탕화면 위젯은 작은 창, 항상 위 표시, 빠른 입력을 제공한다. 초기 데스크톱 대상은 Windows다.
- 사용자는 웹과 위젯에서, AI는 CLI에서 같은 정보를 조회·수정한다.
- 관제 서비스는 사용자의 상시 실행 서버에 설치한다.
- 로컬 및 Tailscale로 연결된 SSH 서버의 프로젝트를 등록한다.
- Codex와 Claude Code용 스킬이 CLI 사용 시점과 기록 규칙을 안내한다.

## 화면과 상호작용

기본 목록 순서는 사용자가 정하고 유지한다. 갱신 때문에 행이 자동으로 이동하지 않는다. 확인 필요 항목은 표시와 필터로 찾을 수 있다. 키보드로 행을 펼치고 접을 수 있고, 색상 외에도 상태를 텍스트로 표시한다.

상세 영역에는 현재 상황, 담당자, 할 일, 메모, 시간순 활동이 있다. 작은 위젯에서 웹 상세 화면으로 이동할 수 있다. 여러 행을 펼칠 수 있으며 목록이 창보다 길면 스크롤한다.

## 데이터 의미

| 항목 | 규칙 |
| --- | --- |
| 프로젝트 상태 | 진행, 보류, 완료 |
| 작업 상태 | 할 일, 진행 중, 확인 필요, 막힘, 완료 |
| 내 상태 | 사용자가 직접 작성한 최신 상태. AI 상태 갱신과 독립적으로 보존 |
| AI 상태 | AI가 작성한 최신 요약. 내 상태 아래에 표시 |
| 작업 기록 | 날짜·시간·작성자·내용이 남는 누적 이력 |
| 메모 | 현황 요약과 분리하여 보존 |
| 실행 신호 | 작업 상태와 별도. 최근 신호가 없으면 실행 여부 미확인 |

작업 하나의 완료가 프로젝트 전체 완료를 뜻하지 않는다. 마지막 업데이트만으로 AI가 현재 실행 중이라고 판단하지 않는다. 기록 시각은 원래 발생 시각과 서버 수신 시각을 구분하며, 화면은 사용자 시간대로 표시한다.

## AI 연동

작업 시작 전에 현황과 할 일을 읽는다. 작업 시작, 의미 있는 진전, 질문·막힘, 완료 시 CLI로 갱신한다. 매 도구 호출을 활동으로 기록하지 않는다. 상태 변경과 해당 이력은 한 번에 저장한다.

CLI 예시(미구현):

```sh
pmw init --name "Example project"
pmw status --json
pmw task list --json
pmw task add "Implement sign-in"
pmw task start T12 --actor codex
pmw status set "Connecting the sign-in form"
pmw task block T12 --reason "Login method requires a decision"
pmw task done T12 --summary "Implemented and verified sign-in"
pmw note add "Consider social login next"
```

폴더별 프로젝트 연결 설정을 사용한다. AI가 작성자를 지정한 값과 인증된 클라이언트의 식별자를 별도로 기록한다. 사람이 작성한 메모를 AI의 요약 갱신으로 덮어쓰지 않는다.

## 연결 끊김

서버 연결 실패를 성공으로 표시하지 않는다. CLI의 임시 전송 대기 기록은 재연결 후 명시적 재전송 또는 이후 호출 시 전송한다. 자동 백그라운드 전송을 제공하면 별도 실행 구성과 상태를 문서화한다. 중복 전송은 중복 기록을 만들지 않으며, 충돌한 변경은 사용자에게 드러낸다.

## 첫 버전 완료 조건

1. 테스트용 프로젝트 7개를 목록에서 읽고 상세를 펼칠 수 있다. 사용자 상태가 AI 상태보다 먼저 표시된다.
2. 로컬과 원격 서버의 CLI가 같은 관제 서비스에 인증하여 상태를 갱신한다.
3. 갱신된 상태와 이력이 웹과 위젯에 새로고침 없이 반영된다.
4. 사람이 적은 할 일과 메모를 AI가 CLI로 읽을 수 있다.
5. 날짜별·프로젝트별 기록을 작성자와 함께 조회한다.
6. 재시작 후 데이터가 유지되고 백업·복원 절차가 동작한다.
7. 인증 실패, 연결 끊김, 중복 재전송, 동시 변경을 검증한다.
8. Windows에서 작은 위젯 창과 항상 위 표시를 실제 확인한다.
9. 드래그로 바꾼 순서가 재조회 후에도 유지되고, 동시 변경 시 부분적으로만 저장되지 않는다.
10. AI 갱신이 사용자 상태를 덮어쓰지 않는다. 삭제한 프로젝트는 목록에서 사라지고 기록은 DB에 남는다.

## 이후 확장

위젯에서 AI 직접 실행, 터미널 제어, 자동 코드 수집, 다중 사용자 조직 관리, 공개 인터넷 배포는 첫 버전에 포함하지 않는다. 할 일을 등록하는 행위는 AI 실행 명령이 아니다.
